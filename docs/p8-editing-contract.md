## P10：高光与输出策略复核

沿用既有路线中的 P10，当前补充职责说明，不新选算法。目标是确定保留的 RAW/线性数据如何形成可靠的预览与导出，为 P11 提供未被不必要裁剪破坏的输入。

现有 `camera-clip` 在白平衡后的相机 RGB 上先执行逐通道 `min(C,1)`，再做颜色矩阵与曝光；它生成输出副本，保留源，但该分支裁剪掉的差异不会因后续降曝光恢复。用户现已拒绝提前裁剪，camera-clip 不进入新编辑器路径；原实现和测试保留作历史参考。P10 在此约束下验证未裁剪路径的高光表现及输出边界，不自动重新引入提前裁剪。

工作范围：

1. 区分传感器已饱和、处理产生但仍有效的超一余量、最终显示范围裁剪；避免把所有大于1的值判为同一情况。
2. 检查不提前裁剪路径在逆光/局部通道饱和时的色彩、层次和曝光响应，说明最终输出的局限；camera-clip 仅可作历史对照，不作为新路径候选自动恢复。
3. 固定编辑与输出边界：源与工作数据保留；不可逆裁剪/编码/量化位置显式；预览与导出使用同一策略。五个 P11 控件的具体位置需与此契约协调。
4. 使用未饱和超一值、部分通道饱和、全部通道饱和的合成样例和授权逆光样张，对照数值、颜色、细节与源不变性；先验收再进入 P11。

P10 处理高光数据和输出规则；P11 提供用户主动调节的五个影调控件。先完成 P10，可避免 P11 高光滑块接到已经丢失有效差异的输入。P10 不自动承诺高光重建，也不重新启用已排除的 P6 肩部；若证据表明需要新映射或重建算法，仍按阶段规则说明选项并由用户确认。

| 数据 | 持有及用途 |
|---|---|
| 磁盘 RAW | 保留原文件，不覆盖；打开成功后不在每次调整时重读 |
| 解码 Bayer uint16 与传感器元数据 | 会话拥有，只读用于处理；保留黑白电平、CFA、拍摄时增益和矩阵，可重新归一化与检查饱和 |

缓存点不调用 P6 肩部，也不作 camera-clip。D4 已确定仅在最终输出副本裁剪；若 P10 新处理依赖 RAW 饱和信息，须将其显式加入依赖。

### 失效规则

缓存身份依赖源、解码/归一化元数据、实际白平衡增益、去马赛克算法与配置，以及尺寸和颜色状态。未命中则重算，不能继续使用过期缓存。

| 操作 | 可复用 | 重算范围 |
|---|---|---|
| 改曝光 | RAW 与相机 RGB | 颜色转换及完整下游编辑；不累乘旧预览 |
| 改色温/色调 | RAW 与元数据 | 归一化、白平衡、去马赛克及全部下游 |
| 改五项影调或饱和度/自然饱和度/HSL | RAW 与相机 RGB，前提是处理位于其下游 | 完整下游编辑链；精确算法顺序仍待后续契约 |
| 改矩阵或输出设置 | RAW 及不依赖这些设置的相机 RGB | 受影响的颜色转换与输出 |
| 全部复位 | RAW；白平衡未变时也复用 RGB | 恢复初始参数；白平衡曾改变则重建 RGB |
| 换照片 | 旧数据只属于旧会话 | 新源、新初始参数、新缓存身份，禁止新旧数据混用 |
| 丢弃缓存 | RAW 与参数 | 重建缓存，结果须与原路径一致 |

### 所有权、错误和导出

- 会话不向界面暴露源/缓存可写像素。现有 ImageBuffer 可变，因此必须限制可写别名，不能仅凭函数参数为 const 就宣称不可变。
- 一次计算绑定完整参数快照、源及输出设置；结果不完整或失败不得发布为有效缓存。若继续显示旧成功帧，应明确新调整尚未成功。
- 处理借用的存储须存活到使用结束；替换缓存不能产生悬空指针。排队、并发及结果提交方式留 D3。
- 内存不足须报告失败或按已定策略释放可重建缓存，不得改写源或静默降低精度。
- 导出从全尺寸源或有效全尺寸缓存与完整参数生成，不能从缩小、裁剪、编码后的屏幕预览反推。

### 内存代价及备选

无行填充的 N 像素：Bayer uint16 为 2N 字节，相机 float RGB 为 12N，合计 14N。6000×4000 示例为 336,000,000 字节，约 320.4 MiB；额外保存归一化 float Bayer 再增加约 91.6 MiB。

以上是存储算术，不是本机实测或峰值上限。解码临时内存、处理结果、替换缓存时的新旧存储、预览、导出和界面纹理仍须计入 D6 实测。

- A：只存解码 RAW，每次重跑全链；缓存少，但曝光也重跑去马赛克。
- B（暂定采用）：RAW + 当前白平衡相机 RGB，支持下游复用，改白平衡时重算上游。
- C：B 加归一化 Bayer 等缓存，减少部分重算，增加内存及失效管理；是否值得待测量。

### 验收要求

1. 曝光 0→+2→−1→0 与直接设置一致，源及元数据不变。
2. 改白平衡后再调曝光保留新白平衡；复位回拍摄时基准。
3. 命中缓存与丢弃后重算一致；改变依赖后不得误命中。
4. 换图或计算失败不混用源/参数，不发布半成品。
5. 验证存储生命周期，测量实际峰值；P9 验证当期参数，P12 补白平衡交互案例。

数值比较沿用对应算法契约；同一确定性路径优先验证逐样本一致。本轮仅写契约，尚未实现或运行编辑会话验收。

| 方式 | 计算期间能否继续调节 | 体验及代价 |

### B 的行为细化（容量与具体交互仍待定）

1. 一次有效参数变更只修改一个控件，但对应完整参数快照。例如先修改色温再修改曝光，第二次的完整状态含新色温；这不等于一次用户操作调整了两个控件。
2. 数字输入以确认输入为一次操作；滑块以控件提交的每个不同有效值为一次操作，按顺序编号。原始鼠标移动事件不直接等同参数操作；具体步长与事件频率需在界面设计中明确。已接受的值不得静默合并或丢弃。
3. 同时只计算一项；成功后将对应参数与画面一并交给界面，在界面完成该次呈现确认后再推进下一项。用户不需要逐帧点击确认；不承诺每帧停留足够长供人逐一检查。
4. 控件可显示最新请求值，但画面旁明确当前已完成的参数/操作编号及待处理数量，避免把旧画面当作最新设置结果。待队列排空，控件和画面一致。
5. 队列有明确容量上限，仅保存参数及身份，不给每个待处理操作复制全尺寸图像；满时暂停接受新的变更并给出反馈，不静默丢失。上限与具体满载交互在 D5/D6 确定。
6. 计算在不阻塞界面事件处理的执行环境中进行；“处理任务串行”不等于“界面冻结”。线程数、框架及通信 API 留 D5，不创建并行像素算法的要求。
7. 复位作为显式操作排在已接受操作之后；导出绑定其在队列位置对应的完整参数，等待前序操作完成。P9 建议导出期间暂停接收调整，换照片只在队列空且无导出时允许，避免引入取消当前会话的额外规则。
8. 处理失败保留最后成功帧，显示失败的操作及原因，并暂停后续队列；用户可重试，或明确放弃失败及后续待处理操作后回到最后成功状态。不得在错误后自动导出旧图并声称对应最新请求。
9. 即使采用串行处理，结果仍核对照片及请求身份，作为混用/重复回调的防护；这不授权乱序呈现。

A 若被选定，可复用上述完整参数、源只读、错误及输出身份约束，但不建立调整等待队列；每次忙碌期间由界面明确拒绝新调整。两者都须在实际机器验证等待体验。

### 排队风险的设计估算

目前没有交互耗时实测；P6/P7 验证没有建立可用于本问题的 benchmark。不能把普通拖动直接判断为无积压。调整幅度小通常不减少当前逐像素路径需要遍历的图像范围；输入速率和单次完成时间才决定积压。

设每秒接受 r 个有效参数值，串行一次计算至呈现可继续下一项的耗时为 T 秒，则理想稳定吞吐为 1/T。持续 rT 大于1时会积压；rT 小于1也不能排除短时突发。固定速率、固定耗时的简化模型中，拖动 d 秒新增未完成量约为 max(0,(r-1/T)d)，停止后清空时间约为未完成量乘 T。实际含排队边界、首尾任务及波动，不把近似结果当精确预测。

示例仅为假设：每秒20个有效值、每次100 ms，处理能力约10项/秒；拖动2秒积压约20项，停下后仍需约2秒清空。这里20 Hz及100 ms都不是本机实测，也不是已选择的输入频率或目标。

源码依据：现有颜色矩阵、曝光和编码各自遍历图像并生成结果；缓存相机 RGB 省去重复解码/白平衡/去马赛克，不会省掉这些下游像素处理。白平衡改变还需重建相机 RGB；未来五项影调和 HSL 的时间尚无实现证据。若每个滑块值都触发全尺寸处理，连续拖动存在明显积压风险，不能承诺常规操作不会触发队列上限。

低分辨率交互计算保留为后续候选；当前先测全尺寸基线，不将其作为本阶段优先实施项。队列容量只限制积压，不提升吞吐；在接受操作前明确步长/采样规则可降低输入量，但必须告知用户，不将接受后的合并丢弃包装成普通优化。最终实测记录输入序列、逐项耗时、最大队长、输入到显示延迟及停止后的清空时间。

- Qt 界面适配：控件、文件选择、队列状态、图像布局/颜色解释、缩放及平移。工作线程不得直接访问 Widgets；跨线程传递的数据所有权和结果寿命须显式保证。

### 图像缩放交互

已确认的是“图像继续放大”，不是新增窗口全屏。以下为可调整的初版交互细节，实际体验在 P9 验收：

- 提供适应视图、100%、放大/缩小按钮、缩放百分比；滚轮或触控板缩放以指针所在图像位置为中心，拖动平移。
- 建议首版手动缩放范围为10%–1600%；适应视图可以低于10%，回到100%有直接入口。该上限是可调整默认值，不将“继续放大”解释为无界内存分配。
- 100%是一图像像素对应一物理显示像素，结合设备像素比例验证；移到不同像素密度的显示器后重新校验。超过100%默认用最近邻显示便于检查像素，缩小时使用平滑显示；这些只作用于查看。
- 放大复用已完成的全尺寸结果，通过视图变换绘制可见区域，不生成与放大倍数对应的巨大整图，不重跑 ISP、不进入编辑队列、不修改参数或 PNG 尺寸。
- 新编辑结果显示时保留缩放比例和图像内查看位置；更换照片初始化为适应视图。复位编辑参数不重置查看位置。
- 验证100%、200%、400%及上限处的像素映射、平移边界、适应视图切换、连续编辑后视点保持；预览显示尚未完成的参数不得冒充已应用。
