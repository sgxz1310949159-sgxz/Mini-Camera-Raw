# 项目基础说明

日期：2026-07-06

## 项目定位

Mini-Camera Raw 是一个学习优先的工程项目。它的价值不在于完整复刻商业 RAW 编辑器的所有功能，而在于把 RAW 处理流水线变得可观察、可解释、可测试。

核心学习目标是理解底层图像原理：

- RAW 传感器数据、Bayer/CFA 排列、黑电平、白电平和动态范围

- ISP 流水线顺序，以及每个阶段为什么存在

- 线性光图像处理与非线性显示空间处理的区别

- 色彩校正矩阵、工作色彩空间和 Gamma 编码

- 影调曲线、直方图、曝光值和裁剪

- 后续扩展：局部对比度、保边滤波、多线程和 GPU 思路

## 工作闭环

每个功能都应该遵循同一个闭环：

1. 先学习原理。

2. 写一份简短设计说明：输入、输出、公式、数据范围、边界情况。

3. 实现最小但正确的 CPU 版本。

4. 用数值测试和视觉检查进行验证。

5. 记录改了什么、学到了什么、还有哪里看起来不对。

这个闭环能防止项目变成零散实验堆，同时也会让最终仓库成为更有展示价值的作品：不仅有代码，也有推理和解释。

### 阶段零：工程底座

目标：在实现图像算法之前，先创建一个能长期推进的工程基础。

产出：

- 公开仓库结构

- MVP 边界和验收标准

- 初始 CMake 与测试计划

- 初始图像数据模型

- 本地学习工作区

学习重点：

- C++ 项目结构

- 图像内存布局

- 位深和数值范围

- 基础测试策略

### 阶段一：RAW 读取与基础 ISP

目标：把 RAW 文件转换成一张可查看的 RGB 图像。

目标流水线：

```text
RAW file
-> LibRaw parse
-> Bayer/CFA buffer
-> black level correction
-> white balance
-> demosaicing
-> camera-to-working-space color transform
-> gamma/display transform
-> PNG/TIFF output
```

```text
RAW 文件
-> LibRaw 解析
-> Bayer/CFA 缓冲区
-> 黑电平校正
-> 白平衡
-> 去马赛克
-> 相机色彩空间到工作色彩空间转换
-> Gamma/显示转换
-> PNG/TIFF 输出
```

学习重点：

- RAW 与 JPEG 的区别

- Bayer 排列和去马赛克

- 黑电平/白电平归一化

- 作为通道增益的白平衡

- 色彩矩阵转换

- 为什么多数调整应发生在线性空间

### 阶段二：影调引擎与临时 UI

目标：加入基础 Camera Raw 风格控制，同时保持核心引擎干净。

优先控制项：

- 曝光

- 对比度

- 黑场 / 白场

- 色温 / 色调

- 基础影调曲线或 Gamma 控制

OpenCV highgui 可以作为临时验证 UI，但 UI 代码必须留在核心引擎之外。

学习重点：

- EV 曝光数学

- S 曲线和对比度

- 直方图和裁剪

- 线性空间调整与 sRGB 空间调整的区别

- 参数范围设计

### 阶段三：色彩与局部光影控制

目标：探索更高阶的色彩和局部影调算法，同时保持项目结构可解释。

候选控制项：

- 饱和度

- 鲜艳度

- RGB 与 HSV/HSL 双向转换

- 简化版 HSL 混色器

- 简化版阴影 / 高光

学习重点：

- 色彩模型取舍

- 饱和度与鲜艳度的区别

- 亮度蒙版

- 双边滤波 / 导向滤波

- 低频光照结构与高频纹理细节

### 阶段四：性能优化与 API 导出

目标：把正确的 CPU 流水线变成更完整的工程作品。

优先顺序：

1. 稳定的单线程 CPU 版本

2. benchmark 工具

3. 多线程循环

4. 内存访问优化

5. 动态库导出

6. Metal Compute 作为可选高级扩展

学习重点：

- 缓存友好的像素遍历

- 内存带宽限制

- CPU 与 GPU 执行模型差异

- C API 设计和内存所有权

- 动态库打包

## 验收类别

每个阶段都应该用五类标准检查：

- 功能验收：功能能端到端跑通。

- 数值验收：公式结果在记录好的容差范围内符合预期。

- 视觉验收：输出没有明显偏色、裁剪、光晕或断层问题。

- 性能验收：对固定输入记录耗时和内存测量结果。

- 学习验收：能在项目笔记中解释对应原理。

## 产品要求更新 — 2026-09-26

项目最终需要支持摄影师多元的编辑选择，不止将 RAW 转成可显示 PNG。用户已确认以下
三项后续必做能力，覆盖此前将其视为可选项的表述：

| 能力 | 已确认要求 |
|---|---|
| 亮度分区调整 | 能分别调整不同亮度区域，不限于全局曝光 |
| 颜色调整 | 提供用户可控的颜色编辑，不限于固定相机到工作空间转换 |
| 连续预览 | 编辑过程中连续观看变化，无需每次修改后单独执行 CLI 导出 |

具体控件、区域定义、公式、参数范围、颜色语义、界面技术、预览/导出一致性及可测量的
延迟/内存目标尚待定义；暂定 P8–P13 顺序见 tasks/plan.md，不新增截止日期。

当前 P6 亮度肩部是已验证的简单公式，不是永久产品要求；以下暂定排除决定为当前
依据，现有实现/测试保留作参考。

本更新仅记录后续要求，不启动 GUI、新依赖、算法修改、优化或发布，也不把 P7 已执行
检查扩大解释为最终编辑器已经完成。
