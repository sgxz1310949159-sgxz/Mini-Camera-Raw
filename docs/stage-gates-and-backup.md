## 备份流程（2026-10-12 修订5：慢盘批次写入）

经用户授权对齐FirstLight Camera 2026-10-10修订5；本节替代Mini修订2的逐对象默认写入方式，保留原有范围、历史备份及多工作区隔离。规则和工具适配验证不等于正式阶段备份；适配检查点尚未执行P9阶段备份；后续正式应用须取得单独授权，实际结果由匹配凭据记录。

### 范围与频率

- 在用户要求、重要原件接收或阶段收尾时集中备份；阶段收尾先整理和提交，再按授权备份。小改动不强制重复备份。
- 原始RAW、代码、参数、依赖信息、文档、学习、认可结果、关键对照、必要失败证据及Git默认保留；新文件默认纳入，不按扩展名排除。
- 使用本地控制目录的routine-scope.json，保持roots/编号/路径映射；嵌套工作区由外层根覆盖，不重复遍历，不跟随链接进入项目外。根目录变化先复核，不静默重编号。
- 延续已有精确排除清单，本次只显式排除工具自身的runtime-cache和派生latest-verification.json，不扩大实验结果排除范围，不删除本地材料。缓存不是恢复依赖，丢失可重建。
- 每次执行先盘点大小。新批次单个新增文件上限2GiB，超限明确拒绝；Mini入口保守阻止含任何超限所选文件的正式执行，需另行核查历史复用或旧格式路径，不能静默漏备。ZIP流启用ZIP64；分组阈值256MiB不是单文件上限。

### 批次、缓存与完整性

- 沿用Mini独立store-v1；旧objects、snapshots、receipts原样保留，schema-1可恢复。不迁移、不重写、不回收历史对象。
- 新默认packs-v2按SHA-256复用旧内容，将新增对象、完整清单、嵌入凭据和独立恢复程序组合成ZIP批次。一般一轮一个文件；大批次先发布.dataNNNN.zip，最后发布.snapshot.zip。
- 每份快照直接记录所有引用位置，不逐代重放，但恢复需要完整存储库中的被引用旧对象及数据批次；不能只复制最后一个清单ZIP。
- 全无实质变化时复用有效快照，unchanged=true，不新建外盘快照/凭据。仅目录mtime变化不触发新快照；文件内容/权限/mtime、目录权限、路径增删、链接目标和范围变化仍参与判断。
- 源哈希缓存最长30天，依据根/库身份、路径、类型、大小、mtime/ctime、权限、设备/inode；元数据不反映的静默损坏不保证立即识别。--full-hash强制源哈希，--audit-objects额外核验历史对象，不作日常默认。
- 新内容计算源SHA，压缩时再次核对源流SHA；本机生成后写外盘.pending，flush/fsync并完整重读目标核对SHA后才原子命名。最终快照发布前重新盘点全部所选根，源变化即失败。
- 历史旧对象按有效凭据、存在且非空复用，已缓存对象元数据改变时重验。批次首次见到、缓存失效/到期或元数据改变时核验批次与对象；已知整体SHA变化直接报错。不靠跳过数据校验提速。
- 有效.snapshot.zip及内嵌匹配SHA的receipt.json才表示内容发布；本机latest-verification仅是派生运行记录。content_verified可能包含缓存和历史复用，不表示当轮逐字节重验全库。
- 使用真实挂载检查及同库O_EXCL写锁；失效锁须先确认进程退出。锁文件不要求fsync，真正备份数据保留fsync。保留中断.pending、孤立批次及历史对象，不自动清理。

### 恢复与Git

- 日常不完整恢复；新工具/重要变更、新介质或读写疑问时抽样。首次Mini适配须验证多根目录、真实RAW/成片/文档、Git bundle和外盘嵌入恢复程序；独立测试库通过不冒充正式库已备份。
- 抽样使用sample_restore_verified；Git独立克隆、预期提交核对及fsck使用git_restore_verified；restore_verified=false只表示未进行全量恢复。抽样失败不能报本轮通过，已发布不可变文件不自动删除。
- Git bundle按当前refs与HEAD生成，匹配缓存与bundle内容时复用；不写死P8分支。工作区.git绝对指针不是独立恢复入口。
- 恢复到不存在的新目录，逐文件核对SHA/大小、独立写入普通文件再建链接，拒绝路径穿越及非目录父路径。不覆盖原件。
- 灾难恢复、重大迁移或用户明确要求才全量恢复。保留全部旧恢复点；单个批次损坏可能影响多文件，校验不能修复；一块U盘仍只有一份外部副本。
- SHA不提供加密或身份认证；不承诺所有者、ACL、扩展属性或创建时间。保留整个存储库和独立恢复程序。

### 操作与阶段关闭

本地Python3.12+入口为build/p8-backup-control/backup_verify.py。默认仅盘点，不建Git bundle或写正式库；获得正式备份授权后才使用--execute。首次正式应用追加--sample，并生成新的实际凭据后才可关闭P9。

```sh
python3.12 -B build/p8-backup-control/backup_verify.py
# 以下仅在另获正式备份授权后执行
python3.12 -B build/p8-backup-control/backup_verify.py --execute --sample
# 有内容疑问时按需追加，不作为日常默认
python3.12 -B build/p8-backup-control/backup_verify.py --execute --full-hash --audit-objects
```

旧格式恢复和新格式恢复由packed_backup.py的restore入口处理；本机工具丢失时可直接用Python运行自有.snapshot.zip恢复，仍需指定完整存储库。旧多根写入程序仅归档保留，不作为未经核查的当前执行入口。

工具、精确范围、机器路径、私人样本及本机性能/验证原始证据保持Git忽略；公开记录只保留规则与验证边界。远端发布和下一阶段启动另需授权。
