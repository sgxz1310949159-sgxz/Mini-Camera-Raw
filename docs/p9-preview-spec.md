## 第一步：可选GUI和显示适配

用户确认采用RGBX64独立副本，以及sRGB窗口缓冲加macOS显示转换。只实现合成图像显示，当前入口尚不提供打开RAW、曝光、导出或查看交互。

- `MINI_CAMERA_RAW_BUILD_GUI`默认OFF，关闭时不查找Qt，不给核心/CLI增加Qt依赖。
- 开启时查找Qt6.11及以上Widgets；实际核验版本为独立安装的6.11.2。macOS生成.app，C++17不变；其他平台未验证。
- `apps/gui_image.h`是应用层适配，不进入核心公开头文件。输入必须为3通道、无CFA、EncodedRgb、UInt16、sRGB原色及sRGB传递，声明范围0–65535且不允许越界。
- 不兼容元数据抛invalid_argument；超过Qt int尺寸限制抛length_error；QImage分配失败抛bad_alloc。非空及输入容量由ImageBuffer已验证的不变量保证。
- 逐行按源stride读取，写入窗口拥有的QImage RGBX64副本；R/G/B原值不变，第四分量65535。显示对象不借用源指针，源可独立修改或销毁。每像素8字节是内存缓冲承诺，不是屏幕位深承诺。
- 已编码像素只标记sRGB，不再次执行传递函数。创建QApplication前设置默认QSurfaceFormat颜色空间为sRGB，使Cocoa绘制缓冲也明确为sRGB；系统管理显示器转换。没有程序手动套用显示器ICC。
- 当前3×2合成图按适应窗口最近邻显示，仅用于检查六块色块。正式缩小平滑、100%物理像素映射、指针锚定和平移仍在步骤6实现，当前静态演示不冒充那些能力。

## 后台解码修复

真实RAW在std::async后台线程首次触发LibRaw栈对象溢出；系统报告Thread stack size exceeded。加入不依赖样张的后台缺失路径测试，可稳定复现Bus error。将decode_raw内LibRaw对象改为unique_ptr堆分配，保持异常安全和原参数，修复后该测试及全套通过。与旧主线程相比，这是适配后台执行暴露的真实缺陷，不通过增大线程栈或忽略异常掩盖。
